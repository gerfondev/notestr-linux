# Notestr Linux 3.5.2

- Sauvegarde automatique d’une seule version précédente lors de chaque mise à
  jour d’une note : le backup reste chiffré, est envoyé sur les relais configurés
  et remplace le backup précédent.
- Nouveau bouton **Version précédente** : charge le backup dans l’éditeur.
  Vérifier le texte puis cliquer sur **Publier** pour restaurer cette version.
- Chaque relais doit accepter le backup avant de recevoir la nouvelle note.
  Le cache local conserve un seul backup par note ; supprimer une note demande
  aussi la suppression de son backup sur les relais.
- Vérification de sécurité actualisée au 23 septembre 2026 : les dépendances
  Python et les bibliothèques natives conservent les correctifs intégrés à
  3.5.1. Aucun correctif supplémentaire disponible dans les dépôts consultés.
- Reconstruction des paquets et contrôle de confidentialité avant publication.

Validation : 41 tests automatisés réussis, tests graphiques GTK/WebKit et export
PDF embarqué réussis. L’audit PyPI des 41 dépendances d’exécution ne signale
aucune vulnérabilité connue. Les 181 paquets système recensés dans l’AppImage
sont à jour par rapport aux index Ubuntu/Zorin consultés. DOMPurify 3.4.15 et
TOAST UI Editor 3.2.2 restent les versions stables disponibles.

Aucun chemin personnel du compte de construction, secret utilisateur, note ou
configuration de compte n’a été détecté dans les sources et les paquets contrôlés.
Les licences et exemples publics des dépendances sont conservés. Le périmètre
et les limites des contrôles sont décrits dans **SECURITY.md**.

Le premier backup apparaît après une mise à jour effectuée avec cette version.
Les deux envois ne sont pas atomiques : si la publication de la note échoue après
celle du backup, ce dernier peut déjà contenir la note encore courante. Actualiser
avant de modifier depuis un autre appareil ; les éditions simultanées ne sont
pas fusionnées automatiquement. Nostr ne garantit pas l’effacement des anciennes
copies sur tous les relais. Les tests de publication sont simulés.

L’AppImage cible Ubuntu 24.04 / Zorin OS 18 amd64, avec glibc 2.39 ou ultérieure.
Sans FUSE, utiliser `--appimage-extract-and-run`. Les versions précédentes et
l’historique Git sont conservés.
